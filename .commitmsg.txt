Replace sessions_spawn with child-process parallelism

The previous cron payload had the agent use sessions_spawn to spawn 6 parallel
sub-agents. That pattern works for spawning, but the agent yields after spawning
and never resumes to run Phase C (merge + email). sessions_yield after
sessions_spawn doesn't reliably wake up cron-scheduled agents.

New architecture: the cron agent makes ONE call to a single Node script
(`scripts/run-aggregator.js`) which uses node:child_process.spawn to run the
6 raw-HTTP sources as parallel Node child processes. All sources hit
Promise.all so they're truly parallel. After all 6 finish, the script runs
`node src/orchestrate.js --merge-only` to merge + dedup + email.

jobwinner.ch is still driven by the calling agent via MCP browser between
Phase A and Phase C - the orchestrator script reads whatever JSON file
Phase B wrote.

No sessions_spawn, no sessions_yield. One script, deterministic.
